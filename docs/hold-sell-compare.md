# 持有与现在卖出的情景比较

这是 [短线观察纪律](strategy.md) 里「继续持有是否还值得」那一段的算法和记录字段。纪律仍以那一段为准：基准是现在卖出，以及从现在起还要再承担的上涨和下跌；基准不是当初的买入成本。这里不另写一套入场、止盈或保护参考规则。

命令：

```
python3 scripts/hold_sell.py docs/examples/hold-sell/synthetic-unknown.json
```

通过只说明十进制条件和输入约定一致。它不表示继续持有更划算，也不表示交易方法有效。程序不下单，不取行情，不连接券商。

## 比较什么

增量净额 = 持有到某一情景后再卖出的净现金 − 现在按所写价格卖出的净现金。

现在卖出和以后卖出各自扣除一次佣金、最低佣金、卖出税率和滑点。滑点先计入成交价，成交金额用这个成交价，不要再减一次滑点金额。最低佣金和按费率计算的佣金取较高的一个，不叠加。增量融资利息只从持有路径扣除，表示现在卖出就不再承担的那一段；已经发生的买入费用和已经发生的利息是沉没成本，不进入增量。

价格单位是元/股。数量单位是股，不是手。金额是元。毛价差是价格相减；净额才是扣费之后的现金差。两者可以不同。

## 输入必须分开

每个价格和概率都要写类别：

| 类别 | 含义 |
| --- | --- |
| `sourced_observation` | 已打开来源的观察。要有来源、检索时间、as-of、会话、单位和复权口径 |
| `user_assumption` | 调用方假设 |
| `hypothetical_stress` | 假设的压力情景 |
| `empirically_estimated` | 只用于概率。本仓库不把它检验成胜率 |

缺一项成本就停止，不把缺项当成 0。`zero_cost_teaching` 必须把每项成本显式写成 0，输出会标明这是教学演算，不是观察到的费率为零。没有标明教学模式、却把成本全部写成 0，也会被标出来。

概率可以省略。省略时仍可计算两结果盈亏平衡门槛，但真实条件期望必须写成「无法估计」。给出的概率无论属于哪一类，都不是已测得胜率。程序不编造概率。

计划快照编号只被引用。新的情景写成带时间的追加，不改旧快照。

## 两结果模型的限度

实现的模型只有 `two_outcome_first_hit`：概率 p 落在上沿，1−p 落在下沿。它是条件演算。下面两件事没有被放进模型，所以真实分析始终是「检查不完整」：

- 持有窗口结束时两边都还没碰到
- 两边都可能碰到时，哪一边先到

盈亏平衡门槛 p* 是条件增量为零的那个 p。它不是概率估计。p* 落在 [0,1] 外面时原样写出，不截断。两边增量相同则门槛无定义。把上沿抬高或把费用改小，只说明假设变了，不能证明继续持有变得更划算。

## 四个结论不要并成持有指令

| 问题 | 这一比较里怎么写 |
| --- | --- |
| 算术 | 增量净额、门槛、可选的条件增量。可以在证据不完整时仍然写出，但必须标明是条件演算 |
| 证据 | 价格、费用、窗口、截止或出处不完整时是「检查不完整」 |
| 结构 | 固定为「本次未评估结构」。结构仍由流动性修复检查另写 |
| 执行 | 板块涨跌幅没写明，或现在价不是已核对观察： 「检查不完整」。T+1、跳空或涨跌停、可卖数量不足、股数不是整手： 「计划按现行规则不可执行」 |

总结论包含「检查不完整」和「无法估计」。执行问即使可以单独写成能够按所写价格卖出，也不写进总结论，更不会变成继续持有的指令。正的条件期望同样不是持有指令。
