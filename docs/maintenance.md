# 仓库维护

支持的用法是在本仓库的完整克隆里阅读和修改。`skills/*/SKILL.md` 留在原位置；普通的 Cursor 或其他代理不会自动安装它们。[llms.txt](../llms.txt) 只做导航。不要把 `skills/` 复制到私人技能文件夹当作安装。文档变更见 [CHANGELOG.md](../CHANGELOG.md)。改完后运行 `python3 scripts/check_docs.py`。通过这次检查并不表示交易方法有效。

分析技能与数据适配分开。现在没有适配器，维护时也不要顺手加一个。

## 怎样扩展

优先改已有的两份技能或 `docs/` 下的说明。

- 新的检查字段：加进 `skills/liquidity-repair`，并在 [覆盖说明](../skills/liquidity-repair/coverage.md) 标明它是已确认读法、原始配方、后续扩展还是未解决。
- 新的证据或成交分级：改 [证据约定](evidence-contract.md)、[交易记录](trade-record.md) 和 [复盘卡](templates/review.md)，两份技能只保留链接。已经写下的计划快照不回改；规则变化写成新版本。
- 新的合成走查：放在 `docs/examples/synthetic/`，标明 `synthetic: true`，写上冻结 as-of 和预期的三问结论。不完整或不可执行的例子不要写成放行。
- 新的单笔过程：放在 `docs/cases/`，标明自述或券商核验，并写明价位不是普遍门槛。
- 取数：现在没有稳定脚本。以后若有只读适配，只做一份，供两个技能共用。不要为收盘、融资和均价各建一个技能或各装一个接口。

未解决的近 20 日窗口、停牌、复权和十字星比例，保持未解决，直到当次配置写明选择。不要在维护时补一个看起来精确的默认倍数。数据最长龄期同样只由调用方填写。

## 公开边界

可以提交：纪律、空白模板、两份技能、合成例子、以及单独授权的单笔过程。

不要提交：账户或券商标识、其他持仓、总资金或总市值、能反推总资金的占比、密钥、私人接收人、例程标识、本机路径、未压缩的原始拉取日志。填好的计划卡和复盘卡默认留在私人位置。已公开的单笔案例是例外，它本身也遵守上面的排除项。

本仓库不收录其他研究仓库的材料。

## 示例钟点

示例配置里的 08:30、09:00 和 15:15 只说明历史计划时点。它们不是原创环境那三条私人例程，也不是准时产出的保证。克隆不会按这些钟点创建任务。若要在任务配置里把收盘检查从「有形态才提醒」扩成「每日三只量能对照」，应写明这是 2026-11-13 起的后续扩展，而不是原始规则。该配置不在本仓库执行。
